# Design principles and assumptions

## Design principles

1. **A mirror, not an oracle.** The tool helps the user see; it does not decide for them.
2. **Transparent, rather than pretending to be neutral.** The framework's own assumptions are written down openly.
3. **State different views fairly.** Each view is stated in a way its own supporters would accept, including views we disagree with.
4. **Values are replaceable.** No one's values are built in.
5. **Know the limits.** Say where the analysis is uncertain, and suggest professional help when needed.
6. **Accessible to everyone.** One web page, nothing to install, no account required, and it can run fully offline.

## The framework's assumptions

Every framework involves trade-offs. This one assumes that:

- causes come in layers: personal, relational, institutional and structural;
- value questions are better posed as questions than answered by the tool;
- each field usually contains different views worth presenting;
- whether an action can be undone deserves particular attention when weighing it;
- the user's own judgment should be the last step of the process.

If these assumptions don't suit you, edit the prompt directly, and feel free to discuss them in Issues.
